01 / PROJECT

From source code to running infrastructure.

This project demonstrates the complete path from a developer push to automated AWS infrastructure, container deployment, application routing and persistent database communication.

01 INFRASTRUCTURE AS CODE
TF

Terraform manages AWS infrastructure.

The AWS environment is represented as code rather than manually recreated through the console. Terraform manages the VPC, networking, security groups, EC2 instances, Amazon ECR and Amazon RDS.

$ terraform plan → terraform apply
02 CI/CD
GH

Automated delivery

GitHub Actions orchestrates infrastructure deployment, Docker image delivery and application verification after code is pushed.

03 SECURE AUTH
ID

OIDC authentication

GitHub requests temporary AWS credentials through OIDC, STS and an IAM role instead of storing long-lived AWS access keys in the repository.

04 CONTAINERS
DK

Docker + Amazon ECR

The Node.js application is packaged into a Docker image, pushed to Amazon ECR and deployed to both application servers.

05 DATA
DB

Private RDS MySQL

Application data is stored in Amazon RDS MySQL. The database is private and receives MySQL traffic from the application security group.

ENGINEERING NOTE

This implementation demonstrates application-level active-passive failover. Nginx runs on App Server 01. Therefore, it does not claim full EC2 host-level or Availability Zone failover. A production evolution could place a managed load balancer in front of multiple application instances.

08 / LIFECYCLE

What happens during deployment?

The workflow coordinates both infrastructure and application delivery rather than treating them as unrelated processes.

01
SOURCE

Push code

A push to the configured branch triggers the GitHub Actions deployment workflow.

02
IDENTITY

Authenticate to AWS

GitHub OIDC, AWS STS and the IAM role establish temporary AWS access for the workflow.

03
INFRASTRUCTURE

Terraform execution

Terraform initializes remote state, validates the configuration, creates a plan and applies required infrastructure changes.

04
DATABASE

Ensure RDS availability

The workflow checks the RDS lifecycle state and starts the database when required before application verification.

05
COMPUTE

Prepare both EC2 servers

Application instances are started when needed, checked for health and their current networking information is discovered.

06
CONTAINER

Build and push image

GitHub Actions builds the Docker image and pushes it to the project's Amazon ECR repository.

07
DEPLOY

Run application containers

Both EC2 servers pull the same application image and run the Node.js service on port 8080.

08
ROUTING

Configure Nginx

App-1 exposes Nginx on port 80 with its local application as primary and App-2 as backup.

09
VERIFY

Test application + database

The workflow verifies application reachability, internal server communication and the database endpoint before deployment is considered complete.
